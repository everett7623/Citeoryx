# WordPress AI 测试按钮在保存后失效

## 现象

AI 提供商和 API Key 保存成功后，页面重新加载设置，但“测试连接”按钮仍为禁用状态。

## 真实信号

- 用户确认问题只发生在保存之后。
- 保存流程会立即调用 `GET /integrations/ai` 刷新状态。
- 代码检查发现该接口把 `AiProviderInterface` 对象传给声明为 `string` 的参数。

## 根因

`AiController::get_status()` 调用 `AiProviderFactory::get_provider_settings()` 时使用了 `$provider` 对象，而不是 `$provider_name` 字符串。PHP 抛出 `TypeError` 后，前端状态刷新失败并继续使用保存前的 `has_*_key = false`，因此测试按钮保持禁用。

## 修复

状态接口改为使用 `$provider_name` 读取非敏感配置，并在保存后状态测试中断言活动提供商的模型配置能够正常返回。

## 教训

保存成功不代表后续状态刷新成功。涉及“保存后启用按钮”的交互，需要同时覆盖写接口和紧随其后的读接口契约。

## 后续案例：浏览器自动填充再次禁用按钮

服务端状态刷新修复后，用户截图显示 Key 标签已经变为“留空则保留”，证明服务端确认了已保存 Key；但密码输入框仍出现自动填充圆点，按钮继续禁用。原因是前端还要求 Key 输入状态为空，并要求模型、地址与保存值完全相等。

测试端点只使用服务端已保存配置，因此按钮是否可用应只依赖活动提供商和服务端的 `has_*_key` 状态。修复后移除对表单当前值的依赖，同时为 Key 输入框声明 `autocomplete="new-password"`，降低浏览器复用登录密码的概率。
