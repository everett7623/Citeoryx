# AI 兼容 API 自动追加路径导致连接失败

## 现象

用户使用 Sub2API，将服务商提供的 URL 填入 OpenAI 兼容 API 设置。页面提示系统会追加 `/chat/completions`，测试连接随后失败。

## 根因

插件把用户输入定义成“基础地址”，在保存校验实例和运行时工厂中分别自动拼接协议路径。第三方网关的入口契约并不一定采用 OpenAI 官方路径，因此请求被发送到错误地址。

## 修复

- 兼容 API 的 `base_url` 字段保留名称以维持存储和 REST 兼容，但语义调整为完整请求 URL。
- OpenAI 和 Anthropic 兼容适配器都原样使用已保存 URL，不追加或删除路径。
- URL 可以包含查询参数，仍要求 HTTPS，并拒绝用户信息和片段。
- 回归测试捕获 WordPress HTTP 请求 URL，并断言它与用户提交值完全相等。

## 教训

“协议兼容”只约束请求头、请求体和响应结构，不能推断第三方网关的路由结构。自定义端点应以调用方提供的完整 URL 为契约。
